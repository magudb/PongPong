# tests/checkpoints/guide_ref_ui - crops of the style guide that have no 1280x720 screen reference (package P28)

`tests/checkpoints/guide_ref/pw1x_<screen>.png` are the seven whole screens of the guide. This folder holds the parts of the guide that only exist inside the
big render `docs/Trætoppen Style Guide Review/refs/style_guide_render.png` (1440 x 8990):

| file | region of the render (x, y, w, h) | what | compared with |
|---|---|---|---|
| `dialogue_box.png` | 684, 1844, 680, 300 | the dialogue panel of guide section 03 (its border box is 660 x 266 at (694, 1854); the crop keeps its 6 px rings and the soft shadow: 10 px of margin on every side) | `python tests/checkpoints/compare_guide.py --ref tests/checkpoints/guide_ref_ui/dialogue_box.png --no-frame-crop --region 0,0,680,300 SHOT.png` (fixture `dialogue_guide`, owner P14; target <= 16, ratcheted: the first accepted run N pins `ceil(N + 0.5)`) |

Generated by `tools/ui/crop_guide_refs.py` (Pillow only; run it with the project venv, isolated: `tools/art/.venv/bin/python -I tools/ui/crop_guide_refs.py`; `--check`
regenerates in memory and fails on any drift). The PNG is written deterministically, so a regeneration is byte-identical. `SHA256SUMS` pins the files and
`ui_conformance.guide_crops_pinned` fails when one drifts. The folder carries a `.gdignore`: Godot never imports these PNGs, python reads them directly.

To replace a crop ON PURPOSE: change `CROPS` in the tool, run it (writes the PNG and `SHA256SUMS`), commit both in the same change and tell the owner of the diff target.
