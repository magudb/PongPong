## 0. The decision in one page

**The user said (2026-10-14):** the game day runs **until 02:00 at night** ("untill 2 at night"). Today the clock runs 06:00-24:00 (`lua/config/game_balance.lua` `time.day_end_hour = 24`) and 24:00 passes the player out.

**What this addendum decides:**

1. `GameManager.hour` is the **raw game hour 6..25**. The hours **24 and 25 belong to the SAME game day** (same `day`, weekday, weather, shop opening day, festival day, once-a-day counters) and are **displayed 00:xx and 01:xx**. The day **rolls and the player passes out at game hour 26 = 02:00** (`time.day_end_hour = 26`).
2. Setting that one number is **not enough**: the built `advance_time()` wraps by `day_end_hour * 60` and restarts at hour 0, so the clock would jump from 01:59 back to 00:00 at the roll. The roll must **restart the clock at `day_end_hour - 24` = 02:00 of the new date**, so every calendar day is exactly 24 clock hours and the clock never jumps backwards (edit C04).
3. **Rate unchanged: 2.0 game minutes per real second.** A game hour stays 30 real seconds, every "x game minutes = y real seconds" figure of the towns / social / ghost designs stays true, the day grows from 9 to **10 real minutes** (+11 %).
4. **Hours of every Lua table are floats of GAME HOURS on the axis 6..26** (6.5 = 06:30, 25.0 = 01:00, 25.5 = 01:30). `GameManager.game_hour(h)` maps an authored `1.5` (below the day start) to `25.5`; the notation `close < open` stays legal and means "after midnight of the same game day". Nothing wraps into the next calendar day.
5. Defaults for everything the user did not answer are in section 3 (8 open questions, each with a default; the design is complete and buildable with every default) and the exact lines of the alternatives in section 9.

**What changes in code (all BUILT files, one fix-round commit):** `game_balance.lua` (1 number + comments), `game_manager.gd` (arithmetic, 3 helpers, 1 clamp, header), `time_manager.gd` (1 line: day fraction), `event_bus.gd` (comments), `tt_format.gd` (1 line: `posmod`), the pins of the 24 hour day in 7 existing `core` checks and 2 existing `area` checks (ids kept, one renamed), 2 NEW `save` checks, the new section `clock26.gd`, the balance sim constant. **What does NOT change:** `world_2d.gd` (the pass-out code is already right for the new day; sha-pinned, D0 owns it and fixes 3 comments), `iso_area.gd`, `day_night.gd` and every key of `ambient.lua` (they already wrap by `fposmod(h, 24)`), `shop_system.gd` (weekday rule), `save_manager.gd` (code), every localization CSV, every Danish string.

## 1. The clock contract (C1-C14; every amendment cites these numbers)

| # | rule |
|---|---|
| C1 | **Raw hour.** `GameManager.hour` (int) is 6..25 in play. 24 = 00:xx, 25 = 01:xx of the same game day. 2..5 exist only between the 02:00 roll and the wake-up (the pass-out sleeps through them; an autosave resumed at 02:xx or a roll during a travel can leave the player awake there). `time_of_day_changed(hour, minute)` carries the raw hour 2..25. The clock hour is never 26. |
| C2 | **Display.** One formatter: `TTFormat.clock(hour, minute)` = `"%02d:%02d" % [posmod(hour, 24), minute]`; `GameManager.clock_hour_of_day(raw)` is the numeric twin. Nothing prints a raw `%02d` of the game hour; nothing compares `hour < 24`. |
| C3 | **Day end and restart.** `day_end_hour()` = 26 (Lua `time.day_end_hour`, fallback literal 26). Valid range `day_start < value < 24 + day_start` (7..29 at the shipped day start 6): anything else falls back to 26, or, when 26 itself breaks the range for a modded day start of 0..2 (`26 >= 24 + start`), to the largest valid value `23 + day_start` (24 at start 1, 25 at start 2: a fallback that is always valid; a day start of 0 has no hour below it, so the pass-out can not be told from the bed in ANY version, the 24 hour base included). The roll sets the clock to `day_roll_restart_hour()` = `max(day_end - 24, 0)` = 2 (0 when `day_end <= 24`, bit-identical to the old behaviour: proved for the day ends 7 / 12 / 22 / 23 / 24 by a model of the OLD arithmetic, `clock26.day_end_hour_config_edges`, 210 cases) and steps the calendar. `advance_time()` conserves calendar minutes: `total_day * 1440 + hour * 60 + minute` grows by exactly the advanced minutes (proved by `clock26.advance_time_conserves_calendar_minutes`, 272 cases). |
| C4 | **Pass-out.** The roll emits `day_ended`, steps the calendar, rolls the weather, emits `day_started`, then `game_event(&"midnight_passed", {day, season})`. The id is kept (reserved by the towns addendum 8.2 and pinned by tests) and means "the day-end roll". WorldRoot2D starts the pass-out sequence on it (iso areas only; the forest clock is paused). **Real midnight (raw 24:00) emits nothing.** A hook for a true midnight needs a NEW name (`clock_midnight`), never a reuse. |
| C5 | **The game day owns the date.** Weekday, `date_text()`, weather, shop opening weekday (`ShopSystem.is_open`, `Hours`), festival day, `total_day`, birthdays, the once-a-day flags (bath, swap, post, `talked_today`) all change at the roll or at the bed, never at 24:00. The HUD shows `Tirsdag 16.` at 23:50, 00:30 and 01:30 and `Onsdag 17.` after the roll. |
| C6 | **Bed.** Opens at `time.sleep_from_hour` (18:00) and stays open to the wake-up: raw 18..25 and 2..5. A bed at raw 24:xx / 25:xx passes exactly one day (`end_day()`: the day had not ended), a bed at raw 2..5 skips no day (`sleep_until_morning()` sees `hour < wake_hour`). Wake-up is always 06:00. |
| C7 | **Night.** `is_night()` = `hour >= 20 or hour < 5` on the raw hour: 20..25 and 2..4 are night. DayNight wraps by `fposmod(h, 24)`, so raw 24..26 sample the keys 0.0..2.0 (colour `576199` -> `5e68a0`, glow 1.0): the same navy night with lantern halos as 23:30 (measured: luminance 0.392 at 23:30, 0.405 at 01:30, 0.982 at noon). |
| C8 | **Saves.** No `SAVE_VERSION` bump. `from_dict` clamps the hour to `restart..end-1`: 6..23 of old saves load unchanged, 24 / 25 are valid, 26+ -> 25, an hour 0 / 1 / negative (a file written right after the old midnight roll) -> 02:00. A slot written at 01:40 round-trips with summary hour 25. |
| C9 | **Data.** Every hour in Lua tables, routines, hours, festival windows, curfew is a float of game hours on the axis 6..26. Nothing is "minutes since 00:00" or "since 06:00" except GDScript validator loops (which must loop `range(6 * 60, day_end * 60, step)`). |
| C10 | **Normaliser.** `GameManager.game_hour(h: float)`: below `day_start_hour` -> `+ 24` (1.5 -> 25.5, 0.0 -> 24.0), 6.0 and up unchanged. The ONE place that knows the wrap; Hours, the routine compiler, `CalendarUtil.hour_in` and the `when=` hour selectors call it. |
| C11 | **Rate.** `time.minutes_per_real_second` = 2.0 stays. The awake day is 20 game hours = 1200 game minutes = 600 real seconds = 10 real minutes. |
| C12 | **Forest.** The clock is paused in Mørkeskoven (lantern-oil clock); `when=night` markers are decided at entry by `is_night()` on the frozen raw hour. A defeat inside the forest cannot meet a pass-out. |
| C13 | **Events at the roll.** One roll = `day_ended`, [`season_changed`], `day_started`, `game_event midnight_passed`, then ONE `time_of_day_changed` at the end of the `advance_time` call (unchanged order). A 50 h skip = two rolls. The deferred autosave coalesces rolls. |
| C14 | **Never.** Never print the raw hour; never test `hour < 24` / `hour <= 23`; never normalise with `% 24` before comparing (use the raw axis or `game_hour`); never add a second implementation of the wrap. |

### 1.1 Real time of one day (rate decision, numbers)

| clock | 06:00 | 12:00 | 18:00 (bed opens) | 20:00 (night) | 23:00 | **24:00** (old pass-out) | 01:30 | **02:00** (pass-out) |
|---|---|---|---|---|---|---|---|---|
| real seconds since waking | 0 | 180 | 360 | 420 | 510 | **540** | 585 | **600** |

* The old day: 18 h = 540 s = 9 min. The new day: 20 h = 600 s = **10 min** (+60 s, +11.1 %). Days per real hour 6.67 -> 6.00. A 28 day season 4.2 h -> 4.67 h; a year of 112 days 16.8 h -> 18.67 h.
* **The two new hours are exactly ONE real minute** (2 game hours x 30 s). This is the honest size of "until 2 at night" at the current rate; section 3 (Q6) names the data-only levers (a later `day_end_hour` up to 29, or a different rate).
* Rate options measured: KEEP 2.0 (chosen). 2.2222 would keep the day at 9 min (20 h in 540 s, a game hour = 27 s) but turns every "x game minutes = y real seconds" figure (oil, closing, festival lengths, walking times in `RouteTable`, the 2.5 real minutes of SV9, `core.time_tick_rate`) into a lie.
* Balance: per game DAY the economy is unchanged (energy and chores bound the day, the clock is paused in the forest); only the real time per day grows. `docs/features/BALANCE.md` real-hour columns grow by 11 % (typical 345 d: 51.8 h -> 57.5 h, casual 919 d: 137.8 h -> 153.2 h, dedicated 185 d: 27.8 h -> 30.8 h); the day numbers do not change.

## 3. The player's night and the defaults for what the user did not say

**What the player sees.** 23:59 -> the HUD clock (P17) reads `00:00`, the date block still says `Tirsdag 16.`; the farm stays the navy night with lantern halos; the bed works; moon crops count a watering; the DAY a shop is open is the game day's (`ShopSystem`'s weekday rule: the flea market's Saturday does not end at 24:00); WHETHER it is open is its opening hours' business (the towns' `Hours` rule, once T-towns-core exists), and every shipped close is <= 23:30, so after midnight the shops are shut by their own hours (the one exception is the ghost family's lantern house, open until 01:00 by the family design's own default). At `towns.curfew` (default 01:30 whisper, 01:45 the night watch walks the player home from a town). At **02:00**: the roll (crops grow, shop restocks, bin pays, autosave), the screen fades (0.7 s), the toast "Du faldt om af træthed og vågner i din seng." (`NOTIF_PASSED_OUT`, world.csv), the player wakes at **06:00 of the next date**, energy and hearts restored, at `farm:from_home` (D0). A bed at 00:30 gives the same morning without the toast.

The core of the change (C03 + C04, `scripts/autoload/game_manager.gd`):

```gdscript
func day_end_hour() -> int:
	var fallback := mini(DEFAULT_DAY_END_HOUR, 23 + day_start_hour())   # 26; 25 / 24 at a modded day start of 2 / 1: always inside the valid range
	var end_hour := int(config_value("time.day_end_hour", DEFAULT_DAY_END_HOUR))
	if end_hour <= day_start_hour() or end_hour >= 24 + day_start_hour():
		return fallback
	return end_hour

func day_roll_restart_hour() -> int:
	return maxi(day_end_hour() - 24, 0)

func advance_time(minutes: int) -> void:
	if minutes < 0:
		return
	var end_minutes := day_end_hour() * 60
	var restart_minutes := day_roll_restart_hour() * 60
	var day_minutes := end_minutes - restart_minutes
	var total := hour * 60 + minute + minutes
	var rolls := 0
	if total >= end_minutes:
		rolls = floori(float(total - restart_minutes) / float(day_minutes))
		total -= rolls * day_minutes
	for i in rolls:
		hour = floori(float(restart_minutes) / 60.0)
		minute = 0
		_roll_day()
	hour = floori(float(total) / 60.0)
	minute = total - hour * 60
```

Why the restart and not the plain wrap: with `day_end_hour = 26` and the old wrap-to-0, 25:59 + 1 min is 00:00 (two hours back), so a 20 h skip lands on 00:00 and a 25 h skip on 05:00. The invariant of C3 (calendar minutes conserved) is what the new check pins for `day_end_hour` 26, 24 and 29.
