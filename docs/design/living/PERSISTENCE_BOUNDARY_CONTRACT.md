# Living completion — selected persistence-boundary contract

## Status and authority

This records the **selected implementation policy**, not a claim that production implements or passes it. Production work is owned separately; integration, integrated runtime verification and independent cumulative review remain pending. The fixture/documentation handoff changes no production code and cannot establish persistence acceptance.

The authoritative proposal is the retained `persistence-boundary-audit1/PROPOSAL.md`, D01–D16, with `decision-register.json` and `acceptance-matrix.json` in the same evidence directory under `living-completion1`. Its original design-only disposition is historical: the later `persistence-implementation1/authorization.json` records authorization to implement and verify the proposal. Proposed result/receipt/projection capabilities below are concepts, **not invented existing API names**. Exact production symbols must be documented against the integrated source by its owner.

## Selected ownership and representation

- **D01 — Bounded attachment:** the existing World owns a copied logical-host attachment record, not a new manager, disk version or cached whole world. Preserve world-v1/player-v3 compatibility fields.
- **D02 — Provenance and capture:** bind that record to the exact World incarnation, p0, original profile object, attachment generation and area. Sample finite current pose/hotbar and explicit host vitals before sanctioned unregister clears aliases or emits callbacks. No lazy profile creation or detached-body reads. Incoming model replacement cannot adopt the old body's data; only authenticated complete rollback may restore old usability without resurrecting a Node.
- **D03 — Source priority:** a legitimate registered same-profile current p0 body wins; otherwise only its same-World/current-area/original-profile departure record is usable. Otherwise refuse. Old exit/unregister cannot overwrite or retire a successor. Explicit rejoin hydrates before readiness; an already configured legitimate replacement remains authoritative.
- **D04 — Live shared data:** gather placed items/orphans, flags, farm and greenhouse state live. Never substitute predeparture whole-world data or cross-area pose. Preserve explicit-load clamps, unknown-map recovery and intentional load-vital recovery. Retained vitals must not fabricate healing, fees or resurrection; legitimate model-owned vital changes require an owned update path, not stale-cache overwrite.
- **D05 — Stable persistence host:** p0 remains the save-format host even when a surviving p1 becomes group-local or another player is ambient. Confine this rule to roster normalization, World/legacy Social persistence projection, whole apply/backup/direct scopes and reward capture. Preserve ordinary registry/group lookup and local-hero Social behavior; `by_player` remains authoritative.

## Selected operation boundaries

- **D06 — Checked gather:** preflight host authority before callbackful normalization. An incoherent present World fails the real save, never falls back to pending data. A genuinely absent World retains opaque pending/empty-new-game compatibility. Writes own a lexical structured gather result; the existing public Dictionary observation facade remains usable, including during load callbacks, without write admission or contamination of an enclosing write's failures.
- **D07 — Admission:** extend the existing GameManager lifecycle boundary over complete synchronous manual/auto writes. First admitted root wins; nested save/load/reset/new-game/delete/quit roots busy-refuse without file/status/timer/notification effects. No implicit queue or newer-operation-wins. Capture exact Save/target/config/run/accounting/profile/World/ordered-section authority before callbacks and consume entry authority before invoking them. Internal autosave composition must not borrow a public ambient token.
- **D08 — Durability and tails:** serializers, validators, backup/quarantine/prune, atomic write and synchronous status/signal/toast tails remain inside the admitted root, with authority revalidation before irreversible work. No player scope or write token spans confirmation/install/shutdown awaits. Existing bool means actual committed bytes: false before commit/busy, true after atomic commit even if presentation is superseded. Suppress stale suffixes; do not fabricate a public integer sentinel. Preserve ordinary failure/status/retry behavior.
- **D09 — Load coherence:** Save retains pending-only World handoff, not eager live application. Successful profile replacement makes the old live World non-saveable until legitimate fresh-scene consumption. Do not serialize its old body into incoming profiles or hide incoherence with pending data. Load-only success is not scene-ready success.
- **D10 — Direct restore:** preserve normal same-model body-present roundtrip and the existing void facade. A proposed checked result lets consequential callers observe unsupported hostless, cross-area, stale-model, foreign-operation or unprovable-binding refusal before mutation, without `state_applied`. Fresh-scene loading remains supported; in-place bodyless map construction is not promised.
- **D11 — Rollback/fallback:** preserve exact section values and reference-graph proof, adding checked World/shared/attachment projection verification without making World an eager applied section. Sanctioned departure may preserve the logical projection through copied data, never body resurrection. Unproven restoration is incomplete. Across primary/backup attempts, revival requires original enclosing-operation proof; successful backup is a new winner. Preserve backup retry after incomplete primary restoration. Arbitrary raw external field writes are not promised automatic undo.
- **D12 — Committed consumers:** direct and disk paths capture exact successful-apply authority after accounting resumes but before UI finalizers, backup toast or public load tails. Preserve direct pre-UI reward capture; raw `load_completed` slot notifications cannot authorize earned reward resumption. Classify other model listeners separately: read-only invalidation or independently authorized idempotent reconciliation need not be disabled. Any affected synthetic-signal fixture migration must be explicit and retain its original evidence.

## Physical limits and adjacent gates

- **D13 — Physical routes:** body-independent persistence does not authorize bodyless travel/sleep/defeat. Refuse unsupported new routes; old await tails revalidate exact attachments and retire only their own holds/fades/busy flags, without adopting successors or replaying costs/day rolls. Preserve a deferred rebuild for one legitimate rejoin against current authored data. Production route verification remains separate.
- **D14 — Bypasses/destruction:** sanctioned unregister is the guaranteed capture path. Raw free/detach/transfer/forged clones without supported exact capture fail closed, never reuse stale saves. Optional pre-exit capture requires ordinary reparent/timing controls. Mandatory destruction evidence includes another real gather/save after deferred actual destruction; detached retention is not equivalent.
- **D15 — Adjacent gates:** restore Social late binding via the existing Svc mechanism, failing closed when context is absent/invalid. Separately, the approved ghost fixture prerequisite completes real protected kin introductions through UI input before reopening ordinary social dialogue. It must retain every original cast assertion, hero/unlock absence, cancellation and later-response control. Only ghost/four-kin fixtures gain the eight first-intro/read-close witnesses; no kin/quest flags or optional menus are injected. Preserve original RED and distinguish focused old-production GREEN from integrated full-family acceptance.
- **D16 — Compatibility:** preserve whole-load/direct issuer stages, early UI private commit, original guards, same-model essential completion, direct pre-UI reward capture, atomic/backup/quarantine behavior and ordinary positives. Result/receipt/projection names remain proposed until verified in production. Capability stand-ins require faithful contracts, not weakened checks or silently changed expectations.

## Evidence and non-goals

The canonical matrix defines proposed scenario families, not executed assertion totals. The implementation owner must bind actual RED/GREEN, whole-unwind results, raw diagnostics, destruction/re-gather, surviving-p1 isolation, load-only incoherence, fresh-scene reload, truthful complete/incomplete rollback, write reentry and direct/disk receipt controls to exact source and mode. A focused cast-section pass does not establish any of those persistence outcomes, the integrated 13-section family, or full core acceptance.

The separate native 38.60 μs / 20 μs miss remains unwaived. Documented CI-scale functional checks, native performance, renderer/export, authored-map placement, hardware/controller/LAN and human acceptance remain distinct. This contract authorizes no staging, commits, push, PR, release, cleanup, renderer change, threshold/coverage/diagnostic weakening or extra correction cycle. Existing authored art/copy is untouched; bilingual copy remains draft with no fabricated human or voice approval.
