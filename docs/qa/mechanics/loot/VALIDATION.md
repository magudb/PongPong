# Dungeon data and economy acceptance

The full staged validator passes 125 rules with zero failures/warnings. Lua 5.4 and Godot LuaRuntime evaluate the required dungeon files; S6 checks the exact declared item count. The new category/source rules and DB1-DB5 cover the actual item, shop, recipe, floor, band, boss, spot, crystal alias and yield tables. Four furniture wanderer sources were corrected to their actual chest tiers. The first band's false crystal source was removed: no crystal node is placed there. The static marker manifest now contains only farm and Hyggebyen; generated placement is validated separately.

`rules-selftest.log` includes the original synthetic negative controls, structured marker parameter/prose controls and a real-data dungeon control plus eleven one-defect probes. `mutants.log` records a green staged control and all fifteen selected pipeline mutants caught by their named rule, including all nine dungeon additions, the implemented-oven/stub contradiction and retargeted static marker defects. No crash guard was accepted as detection. The old odds/TODO mutant anchors were refreshed for the final Lua/CSV spelling; the full pipeline proof in all-mutants.log catches all 57 of 57 mutants after a clean control.

P1 (`pacing.json`) passes all nine fixed gates with 64 saves per profile and 1,000 full dives: median castle days are 251 typical, 689.5 casual and 139 dedicated; the furniture-substitution typical median is 215.5. Luck-zero full-dive means are 2,397.01 uncapped and 2,168.87 capped (90.48% retained), early-cap probability 4.2%, dust 7.21% of gross sold value and band-four rare drops 1.342 per floor. The independent live-data model and source binding are included. These are named modelling assumptions, not telemetry or proof of enjoyable pacing.

`lifetime.log` covers 200 saves per profile over 520 days. Unreached quantiles are explicitly censored as `>520`; they do not imply an item is unobtainable. This model keeps furniture/clothing, sells actual surplus, pays appraisal fees and tracks the existing collection gates. It uses independent Python RNG; earlier runtime-distribution parity and real combat tests are separate evidence.

The final P1 rerun after aligning kitten/puppy item metadata with the existing husbandry bond token passes all nine gates with the same numerical outputs. The live-data binding is refreshed in pacing.json; no price, reward or production timing was changed.
