Trætoppen desktop releases
=========================

Repository: https://github.com/magudb/PongPong
Engine: Godot 4.7.2, pinned with SHA-256 checksums in tools/ci/godot.json.

CI
--
Pushes to main and pull requests run the strict headless playtest for animal,
fairy, hobbit and ghost, plus native Windows and macOS export jobs. Each hero
suite is split into four parallel groups; coverage checks ensure every section
runs exactly once for each hero. The two seeded combat Monte Carlo sections
run at fixed 60 Hz physics without real-time pacing; their game-time limits,
all 180 boss duels and 100-fight/100-ambush samples remain asserted. Other
sections retain normal pacing. Lua 5.4 checks live data independently, and
Xvfb/Mesa supplies software rendering for the art probes. Shared CI CPUs use
a maximum 3x allowance for enemy-logic, room and cached social/routine computation timings;
CI logs show the measured values and limits. The full UI-audit time limit
scales with its screen registry (10 seconds for fixtures plus 3 per screen),
including its intentional focus/localization frame waits. Native reference limits, game-time
assertions, geometry counts and correctness checks stay unchanged. Each export
runner tests the update installer and boots the actual packaged executable.
Windows then installs the NSIS setup EXE, checks its Start menu shortcut and
Apps & Features entry, applies a ZIP update, boots the installed game, and
uninstalls it while retaining a non-installer file. macOS verifies and mounts
the DMG, copies its app as a player would, checks both native architectures,
applies a ZIP update and boots the installed app. All test installs are temporary.
Raw Lua, CSV, JSON and map data are included explicitly. Development exports
use version 0.0.0 and do not perform automatic network update checks.

Production
----------
Push a canonical vX.Y.Z tag, for example:

  git tag -a v0.1.0 -m "Trætoppen v0.1.0"
  git push origin v0.1.0

The tag's version is injected into the game and native application metadata.
Tags with suffixes, leading zeroes or additional components are rejected.
Production release waits for all four character gates and both native export
and smoke checks. The GitHub release is created with the Windows setup EXE,
macOS DMG and both update ZIPs together, their JSON build records and
SHA256SUMS. Failed checks never publish a release. The existing v0.1.0 assets
remain unchanged; the next production tag adds the native installers.

Packages:
  Traetoppen-vX.Y.Z-windows-setup.exe: per-user Windows installation wizard.
  Traetoppen-vX.Y.Z-macos.dmg: universal app and Applications drag-install link.
  Traetoppen-vX.Y.Z-windows.zip: portable x86_64 Traetoppen/ folder.
  Traetoppen-vX.Y.Z-macos.zip: universal Intel/Apple Silicon Traetoppen.app.

Windows: run Setup. The default location is %LOCALAPPDATA%\Programs\Traetoppen;
no administrator account is required. Setup creates a Start menu shortcut and
an Apps & Features uninstall entry. A desktop shortcut is optional. Custom
locations must retain the Traetoppen folder name. Updates preserve Uninstall.exe
and refresh the registered version. Uninstall removes game files and shortcuts;
it leaves saves and files it did not install.

macOS: open the DMG, drag Traetoppen.app to Applications, and eject the image.
For a personal installation, copy the app into ~/Applications instead. Updating
requires a writable installation folder. Move the app to the Trash to uninstall;
saves stay in the normal user-data folder.

ZIP files remain update payloads for both platforms and also support existing
portable installations. No change to the release-feed format is required.

macOS signing
-------------
Without signing secrets, the Godot export has an ad-hoc signature. For normal
downloaded-app distribution through Gatekeeper, configure all these repository
Actions secrets before tagging:

  MACOS_CERTIFICATE_P12       Base64 Developer ID Application .p12 certificate
  MACOS_CERTIFICATE_PASSWORD  Password for that .p12
  MACOS_SIGNING_IDENTITY      Developer ID Application certificate common name
  APPLE_ID                   Apple account used for notarization
  APPLE_APP_PASSWORD         App-specific notarization password
  APPLE_TEAM_ID              Apple Developer team ID

The macOS job imports a temporary keychain, signs the app with hardened runtime,
notarizes and staples it, and packages its update ZIP. It then signs, notarizes
and staples the DMG before removing the keychain. Both downloads therefore carry
their own notarization tickets when credentials are configured.
Secrets never enter the project, artifacts or source. A partially configured
certificate setup fails the build instead of claiming a notarized release.

Godot's platform instructions:
https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_macos.html
https://docs.godotengine.org/en/stable/tutorials/export/running_on_macos.html

Updates
-------
Stable installed builds check the public GitHub latest-release API once per
session from the title. A newer version appears as a title-menu action.
Settings > Updates provides an explicit check and download/install action.
Drafts, prereleases, downgrades, wrong-platform assets, untrusted asset URLs,
missing SHA-256 digests and oversized packages are ignored.

After confirmation, the game downloads to user://updates and verifies GitHub's
asset digest. The install helper independently rechecks the archive, validates
and stages it, then signals that the running game may exit. A playing session
must autosave successfully first. The helper waits for the process to exit,
swaps only the installed game folder/bundle, and relaunches it. A failed swap
or launch restores the previous installation. Failed preparation leaves the
running game open. Cancellation removes a partial download. Read-only and
unexpected install locations are refused; move/extract the release to a
writable normal installation folder before updating.

Public release checks use no embedded token. Private repositories would need
a separate public update feed or an authenticated distribution service.

Local checks
------------
  python3 -m unittest discover -s tools/release/tests -v
  python3 tools/loc/csv_lint.py --strict --quiet
  actionlint .github/workflows/*.yml
  tests/run_playtest.sh --strict --only=release_updates,menus,area_map
  python3 tools/ci/install_godot.py --templates
  python3 tools/ci/install_nsis.py  # Windows only; pins NSIS 3.13 and SHA-256
  python3 tools/release/release.py build --platform macos --version 0.1.0 --production --smoke

Use --platform windows on Windows for its native install/update/uninstall smoke
run. Cross-exporting Windows installers requires a native makensis compiler
(for example, brew install makensis on macOS); omit --smoke when cross-building.
Override the compiler with MAKENSIS or --makensis. Full public CI gates releases.
